# Tools: текущее устройство

## Что было до загрузчика

`/tools` не являлся отдельной подсистемой или хостингом. Это была небольшая
статическая страница из `templates/tools.html.php`:

- ссылки на `/tools/example1` и `/tools/example2`;
- обе страницы — пустые демонстрационные PHP-шаблоны с одним заголовком;
- кнопка `git pull`, отправляющая `POST /update-code` в `SystemController`.

`ToolsController` только регистрировал три точных GET-маршрута и возвращал пустые
массивы для шаблонов. Каталога инструментов, файлового хранилища, метаданных,
загрузки и раздачи пользовательских ресурсов не было.

## Что представляет собой Tools теперь

Tools остаётся частью основного PHP-приложения, но дополнительно работает как
небольшой локальный каталог статических HTML/JS-приложений:

1. `GET /tools` показывает форму загрузки и список опубликованных инструментов.
2. `POST /tools/upload` принимает:
   - один автономный `.html` или `.htm`;
   - `.zip` с HTML и относительными ресурсами.
3. `HostedToolsManager` проверяет пакет, публикует его в отдельный каталог и
   создаёт JSON-файл с метаданными.
4. Файлы доступны по URL `/tools/hosted/<id>/<entry-file>`.
5. `POST /tools/delete` удаляет каталог и метаданные выбранного инструмента.

Прежние `example1`, `example2` и `git pull` сохранены в блоке «Встроенные
действия».

## Выбор стартовой страницы ZIP

Сначала выбирается `index.html` или `index.htm` с наименьшей глубиной вложенности.
Если такого файла нет, выбирается HTML-файл с наименьшей глубиной. Поэтому
поддерживаются как архивы с файлами в корне, так и архивы с общей корневой
папкой.

Все относительные ссылки из HTML сохраняют работоспособность, поскольку
структура каталогов ZIP не меняется.

## Хранение

Каталог выбирается в следующем порядке:

1. переменная `TOOLS_STORAGE_DIR`;
2. `<UPLOAD_BASE_DIR>/hosted-tools`;
3. `<корень проекта>/var/hosted-tools` для локального dev-сервера.

Структура:

```text
hosted-tools/
├── apps/                  # публичные статические файлы
│   └── <tool-id>/
└── manifests/             # непубличные JSON-метаданные
    └── <tool-id>.json
```

В Docker `UPLOAD_BASE_DIR` уже равен `/media/.rpi-mainpage-data`, а nginx
подключает этот постоянный каталог только для чтения. Пересборка контейнеров не
удаляет опубликованные инструменты.

## Ограничения и безопасность

- максимальный загружаемый файл: 100 МБ;
- максимальный размер после распаковки: 512 МБ;
- максимум 5000 записей в ZIP;
- в ZIP обязательно должен быть хотя бы один HTML-файл;
- абсолютные пути, `..`, дублирующиеся пути и символические ссылки запрещены;
- файлы раздаются статически: PHP из загруженного пакета не передаётся в PHP-FPM;
- HTML и JavaScript выполняются браузером, поэтому загружать следует только
  доверенные пакеты.

Для ZIP требуется PHP-расширение `zip`; Docker-образ устанавливает его при
сборке.
